# MineAnime project conventions

## Wiki-sourced content (standing rule from the project owner)
- When a task references a wiki **category** (e.g. Narutopedia `Category:Tools`), implement **every page in that
  category and in all of its subcategories, recursively** (sub-subcategories included). Never stop at the top level.
- Fandom wikis also group pages through Semantic MediaWiki drill-down filters (e.g. "Tool classification").
  Treat those groupings as subcategories too and cover each of them.
- Crawl with the MediaWiki API (`action=query&list=categorymembers&cmtype=page|subcat`, recursing into ns=14),
  record the crawl date and the full member list in `docs/wiki/<category>.md`, and state explicitly which pages
  were intentionally not turned into game content (index/list pages) and why.

## Architecture
- `animecore` holds reusable, anime-agnostic systems; content mods (`narutorpg`, ...) only declare data.
  New mechanics go into the engine first, then get mapped by the content mod.
- Client-only code lives in `src/client/java` (`*.client.*` or `compat.jei`); no `MinecraftClient` in common code.
- Never bundle dependencies (`include`/shadow). Respect `verifyAssetBudget` / `verifyJarBudget`.
- Art: item icons 16x16 or 32x32, Geo textures <= 128px, armor layers (`textures/models/armor/`) the vanilla 64x32 sheet. Item sprites are generated by
  `tools/catalog/` (`build.py` - re-run it instead of editing PNGs/models by hand). Clans: `tools/catalog/clans.py`
  turns `docs/wiki/narutopedia_clans.json` into `tools/catalog/generated/clan_catalog.json`, `villages.py` turns
  `docs/wiki/narutopedia_villages.json` into `village_catalog.json` (both read by DataGen); `natures.py`, `fanon_genjutsu.py`, `taijutsu.py`, `ninjutsu.py` and `schools.py` (in that order) add their jutsu catalogs (run after `clans.py` / `villages.py`);
  `story.py` (after those) turns `docs/wiki/narutopedia_story.json` into `story_catalog.json` (quests + story characters);
  `forms.py` (last) writes `forms_catalog.json` (tailed beasts, curse marks, Kāma, modes, bloodline forms) and
  `assets/narutorpg/awakening_items.json` (the awakening items NarutoForms registers);
  `npc_skins.py` writes the tinted story-character layer textures; `beast_models.py` writes the low-poly form models
  (`assets/narutorpg/form_models/` + `textures/entity/form/`, check them with `form_preview.py out.png`);
  `animations.py` writes cast animations.
  JoJoRPG: `jojo_content.py --extract <crawl.json>` condenses a jojowiki crawl into `docs/wiki/jojowiki_parts_1_2.json`;
  `jojo_content.py` writes `jojo_catalog.json` (styles, techniques, forms), `assets/jojorpg/jojo_items.json` and the
  JoJo sprites; `jojo_story.py` (after it) writes `jojo_story_catalog.json` (chapter quests, characters, night spawns).
  Part 3: `jojo_stands.py --extract <crawl.json>` writes `docs/wiki/jojowiki_part_3.json`; `jojo_stands.py` writes
  `jojo_stands_catalog.json` (every Part 3 Stand as an `animecore:manifestation` + its techniques), `jojo_stand_items.json`
  and the disc sprites; `stand_models.py` the low-poly Stand models (`form_models/stand/`); `jojo_part3_story.py` (last)
  `jojo_part3_story_catalog.json` (152 chapter quests, Stand-user characters).
  `jutsu_descriptions.py` (after the Naruto jutsu catalogs; `--crawl` refreshes `docs/wiki/narutopedia_jutsu_leads.json`)
  writes `jutsu_descriptions.json` - every jutsu's tooltip description.
- Engine wording is neutral; a content mod re-words engine messages via `assets/<mod>/engine_text.json` +
  `AnimeModContext.Builder#overrideText` (use `AnimeText.tr(system, key)` for any message a mod might re-word).

## Production standard (applies to every feature of every mod)
Nothing ships at "it works" - it ships when it feels like the anime. Every new feature must have:
- **Look**: themed by the mod's `AnimeTheme` (HUD panels, title cards, banners); techniques have VFX (`AbilityVfx`
  styles) and a cast animation; manifestations/forms have a model or tinted appearance, aura and summon animation.
- **Feel**: heavy hits use `Juice` (camera shake / impact flash), signature moves get a shout or sound, bosses get the
  intro title card (automatic for `role: boss` story characters), arcs end with the arc banner (automatic in quests).
- **Words**: every technique, form, Stand, character, quest, item and energy pool has a translated name; every
  technique has a description (`ability.<ns>.<id>.desc`, shown in the technique item tooltip) taken from the wiki
  where one exists (`jutsu_descriptions.py`, `jojo_*.py`).
- **Audit**: `PolishAuditTests` (both mods) runs `com.animecore.qa.PolishAudit` - it must pass (missing names /
  descriptions / animations / technique items / models / enemies without techniques fail the build of that mod).
- **Showcase**: add the feature to `tools/qa/showcase_<mod>.txt` and run `python3 tools/qa/showcase.py <mod>`
  (real remapped jars, fresh world from `tools/qa/world_template`); look at `dist/qa/<mod>/contact.png` before shipping.

## Verification
- `./gradlew build` (includes budget checks), `./gradlew :narutorpg:runDatagen`, `./gradlew :narutorpg:runGametest`,
  `./gradlew :jojorpg:runDatagen`, `./gradlew :jojorpg:runGametest` (`:jojorpg:prodClient` runs all three mods together).
- Re-run the relevant `runDatagen` after changing any DataGen provider (lang, models, loot, registries).
- Before shipping jars, run `./gradlew :narutorpg:prodClient -PprodQuickPlay=<world>` (production launch with the real
  remapped jars). The dev environment uses named mappings and hides mixin/refmap problems that crash real launchers.
- Mixins are remapped in bytecode (`loom.mixin.useLegacyMixinAp = false`); do not add `refmap` entries to mixin configs.
